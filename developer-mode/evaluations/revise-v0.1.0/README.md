# revise skill 评测 v0.1.0

这是对 `video2md-revise` 当前指令效果的开发测试，而不是对某个固定“修订模型”的通用排名。输入为 Fun-ASR-Nano-2512 在 ASR 基准 v0.2.0 中的 30 段转写，输入 SHA-256：

`22b8ea47dae3d087192e44aa7cf7d31dd19ca48bb5ac26e96f875336fa882fc5`

质量参考沿用预先固定的 28 条视频可见字幕、628 个规范化字符。比较只在各字幕时间点 ±15 秒的文本窗口内进行自由前后缀 Levenshtein 对齐；它是字幕样本分歧，不是完整音频 CER。

| 版本 | 修订方式 | 完全一致 | 编辑数 | 分歧率 |
| --- | --- | ---: | ---: | ---: |
| 原始 ASR | 不修订 | 22 / 28 | 7 | 1.11% |
| `revised.json` | 润色式改写（反例） | 12 / 28 | 43 | 6.85% |
| `revised-minimal.json` | 最小修订（默认策略） | 26 / 28 | 3 | 0.48% |

## 结论

第一轮的润色式改写降低了字幕样本一致性：它改变了原本正确的词序和表达，虽然可读性可能提高，却不符合“校正转写”的任务边界。因而 skill 已改为默认最小修订：只修正有充分上下文依据的错误；对歧义片段写 `notes`，不猜测补写。

最小修订只改善了四个可明确判断的局部错误：`DFS → BFS`、`格瓦拉拉 → 格瓦拉`、`实施监控 → 实时监控`、`它与 AFS → 他与 AFS`。修订契约禁止把字幕作为输入；但本次执行者处于同一开发会话、可接触评测材料，因此该测试不是盲测，后续应由独立样本和独立执行者复核。

## 工件

- `revised.json` 与 `comparison.json`：保留的润色式反例，展示为什么不能默认改写。
- `revised-minimal.json` 与 `comparison-minimal.json`：当前默认策略的结果与逐样本评分。
- `create_minimal_revision.py`：本次受控测试的四项审计化替换；它不是通用修订器。
- `../../evaluate_revision.py`：可复用于未来“原稿 vs 修订稿”评测的对齐脚本。

运行评测时，必须使用同一个参考集、同一时间窗口和同一规范化规则，不能将不同版本的数字混排。
